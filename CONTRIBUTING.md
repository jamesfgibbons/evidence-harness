# Contributing

> **LANE:** Public collaboration  
> **IS:** Public contribution boundary  
> **IS NOT:** Acceptance of private traces, credentials, or production reports  
> **FORBIDDEN CROSS-OVERS:** Sensitive examples and unreviewed operational integrations  
> **SOURCE OF TRUTH:** Repository issues and pull requests after publication  
> **GATE:** Contributions must preserve the public boundary and pass conformance

Useful contributions include synthetic fixtures, portability improvements, receipt-schema corrections, and evidence-backed changes to resolver behavior.

Do not submit credentials, private prompts, raw traces, client data, internal paths, production identifiers, or incident logs. Use invented values and `.example` domains. Explain which observable failure the change prevents and add a behavioral test when possible.
